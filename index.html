資訊處理：從原始數據到知識Information Processing: From Raw Data to Knowledge

理解「數據→資訊→知識」的層次，是解答高階評析題的關鍵。數據是未經整理的原始事實；資訊是經處理並賦予情境的數據；知識則是對資訊的分析應用，用以辨別趨勢或作出理性判斷。 Understanding the Data → Information → Knowledge hierarchy is essential for high-order evaluation questions. Data is unorganised raw facts; information is data processed into context; knowledge is the analytical application of information to identify trends or make informed judgements.

有效性檢驗與數據驗證的分別Data Validation vs. Data Verification

為應對「垃圾進、垃圾出」（GIGO）問題：有效性檢驗確保數據合理；數據驗證確保數據與來源一致。 To combat Garbage In, Garbage Out (GIGO): validation ensures data is sensible; verification ensures it is correct against the source.

數據表示：數位領域的精確性Data Representation: Precision in the Digital Domain

二進制及十六進制系統是硬件通訊及記憶體定址的語言，必須策略性地掌握。十六進制尤其適合簡潔地表示大型二進制字串（如 MAC 地址）。 Binary and hexadecimal systems form the language of hardware communication and memory addressing. Hexadecimal is valued for representing large binary strings (like MAC addresses) concisely.

技術指引：二進制補碼表示法Technical Guide: Two's Complement Representation

在固定位元系統中表示負整數，採用二進制補碼（Two's Complement）方法： To represent negative integers in a fixed-bit system, use the Two's Complement method:

  1. 從正數的二進制開始。 例：以8位元表示 −3 → 00000011 Start with the positive binary. Example: for −3 in 8-bit → 00000011
  2. 反轉所有位元。 → 11111100 Invert all bits. → 11111100
  3. 加 1。 → 11111101 ✓ Add 1. → 11111101 ✓
所以又點？——溢出誤差So What? — Overflow Errors 溢出誤差是指計算結果超出位元系統的最大範圍，導致符號位元錯誤翻轉，使電腦無法將結果「塞進」分配的記憶體，往往引致軟件崩潰或邏輯損壞。 An overflow error occurs when a calculation result exceeds the maximum range of the bit-system, causing the sign bit to flip incorrectly. The computer cannot "fit" the result into the allocated memory, often resulting in critical software crashes or logic corruption.

電腦系統基礎：硬件與系統邏輯Computer System Fundamentals: Hardware & System Logic

提取─譯碼─執行（FDE）周期是機器組織的核心。中央處理器從隨機存取記憶體（RAM）提取指令，解碼機器碼，然後執行任務——每秒重複數十億次（時鐘頻率）。 The Fetch-Decode-Execute (FDE) cycle is the heartbeat of machine organisation. The CPU fetches instructions from RAM, decodes the machine code, and executes the task — repeating this billions of times per second (Clock Rate).

設備評估：桌上電腦 vs. 智能手機Device Evaluation: Desktop vs. Smartphone

設備 A — 桌上電腦Device A — Desktop

配備獨立顯示卡（專用 GPU）。Features a standalone display card (dedicated GPU).

所以又點？So What? 專用 GPU 能將數學密集型運算從 CPU 卸載，為渲染 4K 影片或高端模擬提供卓越的圖形效能。 A dedicated GPU offloads math-heavy tasks from the CPU, providing superior graphical performance for rendering 4K video or high-end simulations.

設備 B — 智能手機Device B — Smartphone

優先採用快閃記憶體及整合單元。Prioritises Flash memory and integrated units.

所以又點？So What? 快閃記憶體具備更高的數據傳輸速率及更低的功耗，對延長電池壽命和確保流動裝置的可攜性至關重要。 Flash memory offers higher data transfer rates and lower power consumption, critical for extending battery life and portability of mobile devices.

互聯網及其應用：連接與網絡保安Internet & Its Applications: Connectivity and Cybersecurity

隨著由 IPv4（32位元）過渡至 IPv6（128位元）以配合物聯網（IoT），頻寬計算及保安知識的技術精確性是 Band 1 學生的致勝關鍵。 As we shift from IPv4 (32-bit) to IPv6 (128-bit) to accommodate the Internet of Things (IoT), technical precision in bandwidth and security is the key differentiator for Band 1 students.

頻寬計算——二進制精確法Bandwidth Calculation — Binary Precision

⚠ 常見陷阱⚠ Common Trap 切勿使用 8位元 = 1字節 + 十進制 1000 的簡化方法。Band 1 的精確做法是在題目涉及儲存單位時採用二進制（×1024）換算。 Avoid the 8-bit = 1-byte shortcut with decimal 1000. For Band 1 precision, use binary units (×1024) for file sizes when requested or implied.

情境：Scenario: 以 100 Mbps 上載 200 張照片（每張 5 MB）。Uploading 200 photos (5 MB each) at 100 Mbps.

  1. 總位元數： 200 × 5 MB × 1024（KB）× 1024（B）× 8 = 8,388,608,000 位元 Total Size in Bits: 200 × 5 MB × 1024 (KB) × 1024 (B) × 8 = 8,388,608,000 bits
  2. 最短時間： 8,388,608,000 ÷ 100,000,000 bps = 83.9 秒（3位有效數字） Shortest Time: 8,388,608,000 ÷ 100,000,000 bps = 83.9 seconds (3 sig. fig.)

注意：若改用十進制方法（得出約 80 秒），評卷員若期望二進制換算則可能扣分。 Note: Using the decimal method (80s) may lose marks if the marker expects binary conversion for storage units.

公開密碼匙基礎建設（PKI）：雙重機制Public Key Infrastructure (PKI): Dual Mechanisms

1 — 保密性1 — Confidentiality

Eva 以Paul 的公開密碼匙加密。只有Paul 的私人密碼匙才能解密。Eva uses Paul's Public Key to encrypt. Only Paul's Private Key can decrypt.

所以又點？So What? 即使在傳輸途中被截取，檔案對任何人（除 Paul 外）仍無法讀取。 Even if intercepted, the file is unreadable to anyone but Paul.

2 — 身份驗證 / 不可否認性2 — Authentication / Non-Repudiation

Eva 以自己的私人密碼匙為檔案「簽署」。Paul 以 Eva 的公開密碼匙核實。Eva uses her own Private Key to "sign" the file. Paul uses Eva's Public Key to verify.

所以又點？So What? 這確認了檔案確實來自 Eva，且在傳輸途中未被篡改。 This proves the file definitely came from Eva and was not altered in transit.

關聯式數據庫依賴數據完整性維持可靠性。 Relational databases rely on Data Integrity to maintain reliability.

完整性類型Integrity Type 規則Rule 示例Example

乾跑指引：「索引陷阱」Dry Run Guide: The "Index Trap"

⚠ 考試陷阱⚠ Exam Trap 在 Python 中，range(0, 5) 包含 0 但不包含 5 → 索引為 0, 1, 2, 3, 4。 In Python, range(0, 5) includes 0 but excludes 5 → indices 0, 1, 2, 3, 4 only.

示例——反轉數組：Example — reversing an array:

for i in range(0, 5):
    s2[4-i] = s1[i]
i 操作Operation 賦值Value assigned
0s2[4] = s1[0]'S'
1s2[3] = s1[1]'T'
2s2[2] = s1[2]'E'
3s2[1] = s1[3]'A'
4s2[0] = s1[4]'M'

結果：Result: s2 = ['M', 'A', 'E', 'T', 'S']

核對數字驗證：用戶名稱「4B115」Check Digit Validation: Username '4B115'

演算法：S = F + N（班別號碼 + 學號）。若班別（C）為「B」，則 S = S × 3。核對數字 D = S mod 10。 Algorithm: S = F + N (Form + Number). If Class (C) is 'B', then S = S × 3. Check Digit D = S mod 10.

  1. F = 4，N = 11 → S = 4 + 11 = 15F = 4, N = 11 → S = 4 + 11 = 15
  2. 班別為「B」→ S = 15 × 3 = 45Class is 'B' → S = 15 × 3 = 45
  3. D = 45 mod 10 = 5D = 45 mod 10 = 5
結果Result 用戶名稱有效——核對數字 5 與 D 相符。此邏輯可偵測轉錄錯誤，例如誤輸「4A」而非「4B」。 Username is Valid — the check digit 5 matches D. This logic detects transcription errors like typing '4A' instead of '4B'.
